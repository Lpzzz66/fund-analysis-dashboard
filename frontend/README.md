# 基金估值分析看板前端

本目录是正式网页前端，使用 React（前端框架）、TypeScript（类型语言）、Ant Design（界面组件库）、Recharts（图表组件）和 Vite（构建工具）。它只负责页面交互、展示后端已确认的数据和发起 API（接口）调用；不解析 Excel（电子表格）、不计算业务指标、不保存授权码，也不绕过后端权限。

## 页面和真实能力

| 页面 | 路径 | 角色 | 当前真实能力 |
| --- | --- | --- | --- |
| 登录 | `/login` | 未登录 | 用户名密码登录，使用服务端 HttpOnly（脚本不可读取）会话 Cookie（浏览器安全凭据） |
| 初始化 | `/initialize` | 未初始化 | 创建首个管理员；已有账号后自动禁止重复初始化 |
| 公司总览 | `/dashboard` | 全部角色 | 已发布产品规模、净值、公司日收益、覆盖、质量和开放风险数量；可导出总览 |
| 风险概览 | `/risk` | 全部角色 | 查询风险事件；业务员/管理员可记录确认、解决或忽略及证据引用 |
| 产品列表 | `/funds` | 全部角色 | 分页查看产品及最新已发布估值；可按名称、状态、估值日筛选和导出 |
| 产品详情 | `/funds/:id` | 全部角色 | 净值序列、持仓分页、校验结果；支持对应 CSV（逗号分隔文件）导出 |
| 导入中心 | `/imports` | 管理员/业务员 | 创建批次、上传 `.xls`/`.xlsx`、完成处理、查看任务和校验、技术失败重试、受控下载原始文件 |
| 异常复核 | `/reviews` | 管理员/业务员 | 查看复核队列，记录复核决定，发布、驳回、撤回和恢复版本 |
| 邮件接入 | `/mail` | 管理员/业务员 | 查看非敏感设置、测试连接、立即同步、查看同步记录；仅管理员更新授权码和暂停/恢复自动同步 |
| 产品管理 | `/admin/funds` | 管理员/业务员 | 维护产品、别名和份额类别 |
| 科目与模板 | `/admin/subjects` | 管理员/业务员 | 维护科目映射规则 |
| 风险规则 | `/admin/risk-rules` | 管理员/业务员 | 维护六类风险规则版本 |
| 账号管理 | `/admin/users` | 管理员 | 创建、启停、改角色、重置密码、撤销会话 |
| 审计日志 | `/admin/audit` | 管理员/业务员 | 分页查询脱敏审计记录 |
| 系统设置 | `/admin/settings` | 管理员 | 修改白名单系统设置并查看来源 |
| 数据保留与备份 | `/admin/retention` | 管理员 | 查看运维摘要，执行原始文件清理预演和带确认语句的执行 |

页面显示的角色菜单不是安全边界。后端每个路由都会重新验证会话和角色；前端收到 `401`（未认证）应返回登录页，收到 `403`（无权限）应显示无权访问，不能把两者混为一谈。

## 后端数据边界

业务数据唯一来自估值 Excel。网页不会凭空展示以下没有后端接口或可靠数据口径的功能：基准收益、Alpha（阿尔法）、Beta（贝塔）、行业/主题/风格穿透、VaR（风险价值）、压力测试、精确流动性、交易归因、申赎事件、版本差异、统一来源定位和原始文件直达详情。

产品的策略、管理人、别名、份额类别、科目映射和风险规则是人工维护配置；它们不是解析器从 Excel 自动推断的业务事实。

产品详情当前只有三个正式页签：净值序列、持仓、数据质量。资产配置、份额每日数据等能力有后端 CSV 导出，但没有对应的页面 JSON（结构化数据）查询接口，前端不应自行拼接或模拟这些数据。

## 本地开发

环境要求：Node.js 20.19+（JavaScript 运行时）和 npm（Node.js 包管理器）。依赖安装目录可按本机磁盘策略调整；不要把生产 `.env`（环境配置）或授权码放入前端目录。

```powershell
Set-Location F:\AgentWorks\基金分析看板\frontend
npm ci
npm run dev
```

Vite 开发服务器默认使用 `http://127.0.0.1:5173`，将 `/api` 和 `/health` 转发到本机后端 `http://127.0.0.1:8000`。后端启动方式见 `docs/runbook.md` 的本地开发部分。

## 检查命令

```powershell
npm test -- --run
npm run typecheck
npm run build
```

`build`（构建）会先运行 TypeScript 编译检查，再生成供 Caddy（网页服务器）提供的静态文件。生产环境不运行 Node.js 前端服务。

## API 调用原则

- 使用 `src/api/` 下的适配器，不在页面中重复拼接路径或响应解包逻辑。
- 所有请求使用同源 Cookie 凭据；当前接口不使用 `Authorization: Bearer`（令牌授权头）作为网页登录方式。
- 金额、净值、比例和阈值按字符串接收，展示时再格式化，避免 JavaScript 浮点误差。
- 写操作成功后重新读取服务端状态；不要只修改本地页面状态。
- 下载接口返回文件流，不能按 JSON 解析；导出由后端记录审计并负责 CSV 公式注入防护。
- 邮箱授权码提交成功后立即清空输入框；前端不写入浏览器存储、日志或 mock（模拟数据）。

`src/mock/`（模拟数据目录）仅供早期视觉原型参考，不被正式路由和 API 适配器引用。新增页面前必须先确认后端已有真实接口和字段，不能用静态卡片掩盖缺失能力。
