# 数据模型与导入状态

## 1. 建模原则

数据分为四层：

1. 原始层：原文件、邮件信息、哈希和保存位置。
2. 标准化层：解析后的产品、份额、科目和持仓数据。
3. 分析层：收益、回撤、集中度、公司指数和风险事件。
4. 展示层：面向页面的查询结果和覆盖率状态。

原始层和已发布标准化层不可被普通编辑直接覆盖。修订通过新导入版本完成。

## 2. 核心实体

### 2.1 账号和审计

- `user_account`（用户账号）：账号、Argon2id（密码哈希算法）密码哈希、角色、状态、失败次数、锁定时间和最后登录时间。首期角色只有 `admin`（管理员）、`operator`（业务员）和 `viewer`（普通看板）。
- `user_session`（用户会话）：不可读的 SHA-256（安全哈希）会话令牌摘要、过期时间、撤销时间和设备信息。账号停用、改密、管理员重置密码或管理员撤销会话都会使相关会话失效。
- `audit_log`（审计日志）：操作者、动作、资源类型、资源编号、前后摘要、原因、时间和结果。
- `system_state`（系统状态单例）：初始化时间和白名单非敏感系统设置 JSON（结构化配置）；不保存数据库连接串、会话密钥、邮箱授权码或密码。

首次初始化只在数据库没有任何用户时创建第一个 `admin`（管理员），初始化完成后接口拒绝再次初始化。连续 5 次密码错误会锁定账号 15 分钟；登录成功后清零失败计数。登录失败审计只保存用户名摘要和失败原因，不保存密码或会话令牌。

### 2.2 产品主数据

- `fund`（产品）：标准名称、代码、成立日期、策略、负责人、状态、备注。
- `fund_alias`（产品别名）：名称、来源位置、匹配优先级、有效期。
- `share_class`（份额类别）：产品编号、份额代码、名称、启用和停用日期。
- `subject_mapping`（科目映射）：原始科目代码或前缀、名称匹配、标准类别、是否叶子、是否计入持仓、规则版本。
- `parser_rule_set`（解析规则集）：规则版本、适用模板、启用时间、停用时间。
- `risk_rule`（风险规则）：规则类型、适用范围、阈值、严重度、有效期和版本。同一 `rule_code`（规则编码）的修改、启用和停用都创建新版本，旧版本只读保留。

### 2.3 导入和版本

- `source_message`（邮件来源）：邮件编号、Message-ID（邮件唯一标识）、发件人、主题、接收时间、同步批次。
- `source_file`（原始文件）：原始文件名、哈希、大小、来源、保存对象名、保留到期日。
- `import_batch`（导入批次）：来源、创建人、文件数、批次状态、开始和结束时间。
- `import_batch_file`（导入批次文件关联）：批次、原始文件和是否重复。相同文件哈希可以被多个批次引用，但每个批次只建立一次关联。
- `background_job`（后台任务）：任务类型、资源编号、状态、尝试次数、最大尝试次数、锁定时间、开始/结束时间、错误编号和下次重试时间。
- `valuation_version`（估值版本）：产品、估值日、版本序号、解析规则版本、状态、发布人、发布原因。
- `validation_result`（校验结果）：版本、规则编号、等级、实际值、期望值、差异、来源定位。
- `field_provenance`（字段来源）：标准字段、原始工作表、行列、原始文本、转换方式。

唯一业务键不是“产品加日期”这么简单，而是：

`fund_id + valuation_date + version_no`

同一产品同一估值日只能有一个已发布版本；待复核和已替代版本可以有多个。

### 2.4 标准化数据

- `fund_daily_snapshot`（产品每日快照）：总资产、总负债、基金资产净值、单位净值、累计单位净值、昨日净值、周期收益、累计派现、利润字段、可用头寸。
- `share_class_daily_snapshot`（份额每日快照）：份额类别、净资产、实收资本、单位净值、累计单位净值、周期收益。
- `account_subject_daily`（科目每日明细）：原始代码、原始名称、标准类别、层级路径、成本、市值、权重、估值增值、快照版本。
- `position_daily`（持仓每日明细）：证券代码、名称、市场、账户、数量、单位成本、成本、市价、市值、净值权重、估值增值、停牌信息。

所有标准化明细都关联 `valuation_version_id`，因此不同版本可以并存和对比。

### 2.5 分析和风险

- `analysis_run`（分析运行）：触发估值版本、触发原因、输入版本范围、口径版本、状态、错误信息和时间。
- `fund_metric_daily`（产品每日指标）：日收益、累计收益、回撤、峰值、波动统计所需字段、集中度和资产比例。
- `company_metric_daily`（公司每日指标）：公司综合指数、公司日收益、覆盖产品数、总净资产和有效权重。
- `risk_event`（风险事件）：规则版本、产品、估值日、严重度、首次触发时间、当前状态、处理意见、证据快照、处理人、处理时间和证据引用。事件只能通过处置接口改变状态，规则版本变更不会删除或重写历史事件。

系统设置白名单为 `source_retention_days`（原始文件保留天数，1--3650）、`task_concurrency`（任务并发数，1--16）、`data_lateness_days`（数据迟到容忍天数，0--30）、`mail_sync_interval_minutes`（邮件同步间隔，1--1440）、`backup_retention_days`（备份保留天数，1--3650）和 `timezone`（有效 IANA 时区）。接口返回 database/environment/default（数据库/环境/默认）来源标识；当前 worker（任务进程）和 retention（清理服务）仍读取环境配置，数据库设置不会热更新现有进程。

## 3. 版本状态机

估值版本状态：

```text
received
  → parsing
  → validating
  → publishable ──发布──> published
  → pending_review ──通过──> published
  → rejected

published ──新版本发布──> superseded
published ──撤回──> revoked
superseded ──恢复──> published
```

补充规则：

- `failed` 表示技术处理失败，可以重试；不等同于业务驳回。
- `duplicate` 表示文件哈希或产品日期版本已存在，不创建新的业务版本。
- `non_valuation` 表示收到的附件不是估值表，保留来源记录但不进入业务数据。
- 待复核版本不能被看板查询。
- 已发布版本不能修改明细，只能通过新版本替代或恢复。
- 恢复旧版本仍产生新的发布动作和审计记录，不把旧时间线抹掉。

## 4. 导入流程

### 4.1 文件接收

1. 接收文件并记录来源。
2. 校验扩展名、大小、文件头和哈希。
3. 哈希已存在时标记重复，不重复解析。
4. 将文件保存为随机对象名，原始文件名只作为元数据。
5. 创建导入批次和处理任务。

当前实现的文件接收只接受 `.xls`（老式 Excel）和 `.xlsx`（新式 Excel）。`.xls` 必须通过 OLE（复合文档）文件头检查；`.xlsx` 必须通过 ZIP（压缩归档）文件头、基础工作簿成员和归档完整性检查。接口进程在 `complete`（完成批次）时只创建 `background_job`（后台任务），不在请求进程内执行 Excel 业务解析；任务处理器随后读取随机对象名，调用统一解析器、标准化落库和校验服务。

任务领取在执行解析前使用独立短事务提交，把 `pending`（待领取）、到期的 `retry_due`（待重试）或租约超时的 `running`（运行中）任务改为 `running` 并生成随机租约令牌。调用方事务必须保持干净，避免领取动作提交业务方尚未完成的其他变更。PostgreSQL（关系型数据库）使用 `FOR UPDATE SKIP LOCKED`（跳过已锁定行）预留并发领取能力；完成和失败操作必须匹配当前租约，旧任务进程不能覆盖重新领取后的状态，业务写入在租约失效时整体回滚。任务到期重领仍受 `max_attempts`（最大尝试次数）限制，达到上限直接标记失败。SQLite（本地数据库）测试使用简单事务锁语义。临时文件、随机对象名和配置根目录校验由接收模块统一处理，原始文件名不会参与路径拼接。

`.xlsx`（新式 Excel）接收会限制压缩包成员数和总解压大小，解析器同时限制工作表数、单表行数和列数，避免异常工作簿耗尽 2C4G（2 核 4GB 内存）服务器资源。超过限制的文件按单文件失败隔离，不中断同批次其他文件。

数据库迁移 `0003_import_job_lease`（租约字段）和 `0003_job_lease`（领取查询复合索引）保持串行依赖；后者不重复添加字段，回退到前一个版本时只移除索引并保留租约字段。生产迁移必须使用 `alembic upgrade head`（升级到最新结构），不手工改表。

任务处理按原始文件逐个隔离：无法识别产品或估值日期不创建业务版本，只记录复核审计；已处理过的原始文件按 `source_file_id` 幂等跳过，已完成批次重复触发时也只返回重复统计。解析成功后创建新的 `valuation_version`（估值版本），写入快照、科目、持仓、份额和字段来源，再运行校验。当前任务处理器已实现，但独立 worker 进程和任务状态 API 仍待后续批次接入。

科目落库会读取有效期内的 `subject_mapping`（科目映射）规则：代码前缀和名称片段均可匹配，优先使用更具体的规则；匹配成功后保存 `standard_category`（标准类别）和 `include_in_holdings`（是否纳入持仓）快照。未匹配科目不猜测类别，保留原始科目并标记为不纳入资产配置，后续由维护页面补充规则。

### 4.2 解析

1. 定位“科目代码/科目名称”表头，不依赖固定行号。
2. 从前几行识别估值日期、产品名称和单位净值。
3. 解析科目代码、科目名称和各数值列。
4. 统一日期、金额、百分比、证券代码和空值。
5. 构建科目树并识别叶子节点。
6. 识别产品摘要、份额类别和周期收益。
7. 写入标准化候选数据和字段来源。

### 4.3 校验

阻断级：

- 无法识别产品或估值日。
- 无法定位核心字段。
- 资产类合计减负债类合计不等于基金资产净值，超出容忍差异。
- 份额类别净资产合计与产品净资产不一致。
- 产品和估值日与已识别主数据冲突。

警告级：

- 净值日收益与今昨净值计算有差异。
- 数量乘市价与市值有差异。
- 新增科目或模板字段变化。
- 单票、前五大、现金、杠杆或回撤触发风险规则。
- 与上一版本相比净资产、持仓或净值跳变。

提示级：

- 文件名日期与表内日期不同。
- 工作表名称不是标准产品名。
- 百分比或金额为文本格式。
- 该日期缺少其他产品。

### 4.4 发布和重算

发布事务包含：

1. 锁定产品和估值日。
2. 将版本状态改为已发布。
3. 将同产品同日期其他已发布版本改为已替代。
4. 写发布审计日志。
5. 计算受影响的产品日期范围。
6. 创建产品分析和公司分析任务。

如果修订或撤回了历史日期，产品指标从该日期往后重算；公司指标从受影响的最早日期往后重算。计算时读取完整已发布历史作为收益和指数链的上下文，但每次分析运行只落库受影响日期范围，避免日常发布重复写入全部历史。指标查询按产品、估值日选择覆盖该日期的最新成功分析运行；更新运行仍在排队或已失败时，接口明确返回等待或过期状态。

## 5. 历史版本对比

版本对比默认比较：

- 基金资产净值、资产、负债、单位净值、累计单位净值。
- 份额类别净资产和单位净值。
- 资产分类市值和权重。
- 持仓增减、数量、市值和权重。
- 校验结果和解析规则版本。

对比结果分为新增、删除、增加、减少、变化比例和无法比较。无法比较不能默认为零。

## 6. 清理规则

清理只针对 `source_file` 对应的原始对象，不删除标准化数据和审计记录。执行前检查：

- 到期日是否已到。
- 是否仍有待复核任务引用。
- 是否已经完成备份。
- 是否被审计锁定。

清理任务每次产生一份清理日志，包含文件数量、大小、跳过原因和结果。

当前实现默认从 `SOURCE_RETENTION_DAYS=365`（原始文件保留天数）计算滚动到期日，也接受单文件的 `retention_expires_on`（指定到期日）。清理服务支持 `dry_run`（预演）和正式删除两种模式，并将结果写入 `audit_log`（审计日志）；原始对象删除前必须通过待复核、任务状态、审计锁和成功备份四项检查。数据库备份状态同样写入审计日志，失败结果可被系统设置/运维查询使用。
