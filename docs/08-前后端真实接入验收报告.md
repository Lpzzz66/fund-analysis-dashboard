# 前后端真实接入验收报告

更新日期：2026-08-26
验收分支：`feature/scope-convergence`（范围收敛功能分支）

## 1. 验收目标

本轮把早期视觉 Demo（演示原型）收敛为真实业务前端，并与现有后端接口闭环。业务事实只来自估值 Excel（电子表格）及其解析、标准化、校验和分析结果；系统不补充行情、基准、基金经理、策略分类或人工猜测数据。

验收原则：

- 页面显示的业务数字必须来自后端接口，不能使用固定日期、固定产品或模拟指标。
- 页面按钮必须有真实接口和明确状态语义；没有接口闭环的入口直接不进入正式页面。
- 普通看板、业务员和系统管理员的页面权限与后端鉴权保持一致。
- 写操作成功后重新读取服务器状态，不把浏览器本地状态当作最终结果。
- 原始文件下载、邮箱授权码和文件清理遵守后端权限、审计及路径安全边界。

## 3. 接口与数据边界

正式前端统一通过同源 `/api/v1`（第一版接口前缀）访问后端，并携带安全会话 Cookie（浏览器会话凭据）。JSON（结构化数据）、CSV（逗号分隔数据）和 Excel 二进制响应由同一请求适配器处理；非 JSON 的失败响应不会把代理或服务器内部文本展示给用户。

已确认的关键边界：

- 看板只读取 `published`（已发布）估值版本。
- 分析状态和实际分析运行编号同时返回，旧分析结果不能冒充当前结果。
- 导入批次、产品、持仓、复核、用户、科目映射、风险规则和审计列表均使用服务端分页。
- 风险规则编辑只提交允许生成新版本的字段，不提交编号、规则编码或历史版本号。
- 科目映射编辑只提交可修改字段，不提交编号和只读状态。
- 原始文件下载返回 Blob（二进制对象），不会按 JSON 解析而丢失文件内容。

## 4. 权限与敏感数据

- `viewer`（普通看板）只读看板、产品和风险结果。
- `operator`（业务员）可上传、复核发布、维护业务目录和执行邮件运营。
- `admin`（系统管理员）另可维护账号、系统设置、邮箱授权码和原始文件清理。
- 前端路由和按钮做体验层权限控制，后端鉴权仍是最终安全边界。
- 邮箱授权码提交成功后立即清空输入框，不回显、不写浏览器持久存储。
- `.env`（环境配置文件）、密码、授权码、令牌和 `.zcode`（本地代理工作目录）不得进入版本库。

## 5. 已删除的虚构承诺

正式生产页面不再引用 `src/mock`（早期模拟数据归档）。以下无数据或无接口闭环的入口已从正式页面剔除：策略和基金经理信息、外部基准、资产配置占位页、份额日序列、完整版本差异、网页目录扫描、重新解析、邮件附件导航、科目映射试跑、风险规则试算、假导出和仅弹提示的按钮。

`src/mock`（早期模拟数据归档）当前不参与入口、路由、构建后的业务调用或生产运行，仅保留用于追溯早期视觉原型；后续清理必须遵守仓库文件删除纪律。

## 6. 自动化验收

本轮最终门禁包括：

- 后端 pytest（Python 测试）全量通过。
- 后端 Ruff（静态检查）和格式检查通过。
- 后端 ty（类型检查）通过。
- 前端 Vitest（单元测试）全量通过。
- 前端 TypeScript（类型检查）通过。
- 前端生产构建通过。
- Docker Compose（容器编排）开发及生产配置解析通过。
- GitHub Actions（GitHub 自动化检查）同时执行后端测试、前端测试、前端类型检查和前端生产构建。
- 浏览器完成真实登录、公司总览、导入、复核、邮件、管理和清理预演的基本流程检查。

详细命令结果和浏览器实测结论以本轮最终提交记录为准；任一门禁失败不得标记本轮验收完成。

## 7. 保留限制

- 本轮不执行 1,434 张历史估值表的生产迁移，也不处理 6 组 gz（压缩归档）冲突。
- 邮件真实连接需要有效的专用 QQ 邮箱配置和授权码；自动化测试不连接真实邮箱。
- 文件清理浏览器验收只执行预演，不删除真实原始文件。
- Windows 客户端封装不属于本轮真实网页接入范围，后端接口和同源网页保持可封装边界。
