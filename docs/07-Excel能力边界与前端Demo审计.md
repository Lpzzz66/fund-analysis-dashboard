# Excel 能力边界与前端 Demo 审计

状态：2026-08-26 审计基线

## 1. 审计结论

本项目的方向没有根本性跑偏，但当前需要纠正三个层次的问题：

1. `01-产品设计基线` 已明确排除了外部行情、交易流水、申赎流水和合同文本能力，总体边界是正确的。
2. `02-页面与交互设计` 把一批“理论上可由 Excel 推导”的能力直接写成首期页面承诺，没有同步约束到当前解析字段、查询接口和实际覆盖率。
3. 前端 Demo 的全部业务数据来自模拟生成器，不是三份样本或历史目录。页面可作为布局和交互草图，但不能作为功能完成度、计算口径或数据真实性的验收依据。

最需要立即处理的不是删除所有分析功能，而是把它们分为：

- Excel 可以准确提供，当前链路已具备。
- Excel 可以提供，但解析器或接口尚未闭环。
- 只能通过人工主数据提供，且原始需求没有授权扩展该数据源。
- 仅靠估值表无法准确提供，首期必须移除或明确延期。

## 3. 历史 Excel 的真实数据边界

### 3.1 当前解析器已稳定取得

下列字段在 2,787 张文件中均为 100% 非空：

| 字段组 | 字段 |
|---|---|
| 资产负债 | 总资产、总负债、基金资产净值 |
| 净值 | 单位净值、累计单位净值、昨日单位净值 |
| 收益 | 日、周、月、年、成立以来累计收益率 |
| 流动头寸 | 今日可用头寸 |

明细规模：

- 每张表科目数 17--88，中位数 58。
- 每张表持仓数 0--22，中位数 10。
- 每张表均有 2 个份额类别。
- 2,787 张表共解析出 28,720 条持仓。
- 主目录 1,434 张中，现金类科目覆盖 1,434 张、股票 1,422 张、基金 376 张、债券 28 张、回购 771 张、融资融券相关科目 1,271 张。

因此净值、收益率、回撤、资产负债、资产配置、持仓、集中度、现金与杠杆类分析都有真实 Excel 基础。

### 3.3 Excel 部分包含，但不能假设全量可用

- 账户和市场信息存在于部分科目层级中，范围收敛批次已将明确祖先层级提取为可空字段并保存原始科目与源行。
- 对 28,720 条持仓使用正式解析器回归，6,286 条存在明确账户提示，27,811 条存在明确市场层级。市场高覆盖来自原表中的“上交所 A 股、深交所 A 股、港股通”等祖先科目，不是根据证券代码推测；没有明确层级时仍为空。
- 申购、赎回相关科目只在 137 张表中出现，而且是估值日余额，不是逐笔交易或完整现金流事件。
- 停牌信息有专用列，可以展示表内状态，但不能代表外部市场的实时停复牌状态。

页面应允许市场、账户为空，并只在数据实际存在时提供筛选选项。

### 3.4 历史 Excel 完全没有

对 2,787 张文件全部单元格扫描，以下内容出现次数均为 0：

- 产品策略
- 负责人或基金经理
- 业绩比较基准

因此产品列表和详情中的策略、负责人、基金经理、基准都不能自动来自本系统唯一业务数据源。人工维护在技术上可做，但会扩展原始需求的数据来源；在用户再次确认前应从首期分析和筛选中移除，而不是用模拟值填充。

### 3.5 仅靠估值表不能准确完成

以下能力需要新数据源，不能用估值表余额或历史净值伪装为精确结果：

- 基准超额收益、Alpha（阿尔法）、Beta（贝塔）、跟踪误差和信息比率。
- 行业、主题、风格暴露和准确的证券分类穿透。
- VaR（风险价值）、CVaR（条件风险价值）和压力测试。
- 精确流动性天数、成交容量和冲击成本。
- 合同、监管和投资授权限额自动判断。
- 精确交易归因和单券收益贡献。
- 精确申赎、分红和现金流事件。
- 财务级当日盈亏、累计盈亏和现金流调整后的金额收益。

表中的已实现收益、可分配利润和申赎应收应付款余额可以原样展示并注明口径，但不能代替上述能力。

## 4. 需求与设计文档审计

### 4.1 `01-产品设计基线`

结论：总体正确，应继续作为最高产品边界。

需要收紧的表述：

- 账户和市场已经按 Excel 明确祖先科目提取并作为可空字段入库，不按证券代码或产品名称猜测。
- 科目和持仓已经保存工作表、源行及原始科目代码；统一字段来源查询接口仍未闭环，首期页面不能据此承诺所有数字均可点击定位。
- 季度收益、累计派现、份额资本和份额日收益已经完成解析与入库，正式前端仍需接入真实查询或导出接口。

### 4.2 `02-页面与交互设计`

文档中没有直接承诺 Alpha、VaR 等高级外部能力，但存在以下过度设计或未约束承诺：

| 位置 | 当前设计 | 判断 | 建议 |
|---|---|---|---|
| 产品列表 | 策略、负责人筛选和展示 | Excel 无数据 | 首期删除 |
| 产品管理 | 策略说明、负责人 | 只能人工维护 | 原始需求未确认，首期删除或标为可选主数据 |
| 持仓 | 每条均展示市场、账户 | 后端已按明确祖先层级提取，可空 | 保留可空展示；当前页面接口无市场、账户筛选和穿透操作 |
| 份额类别 | 资本、日收益 | 后端已完成解析和落库 | 保留，待正式页面接口接入 |
| 公司最大回撤 | 总览卡片 | Excel 历史可计算，但当前接口不返回 | 保留为待实现，不得硬编码 |
| 公司指数曲线 | 多区间曲线 | Excel 历史可计算，当前只有最新公司指标 | 增加正式序列接口 |
| 来源入口 | 每个关键数字可定位原表 | 当前没有统一来源查询接口 | 在 API 闭环前隐藏或降级为原文件下载 |
| 风险规则 | 11 类首期规则 | 后端只实现 6 类 | 页面只展示后端支持的 6 类，其余分批实现 |
| 邮件配置 | 网页保存授权码 | 后端已提供受控秘密文件写入接口 | 仅管理员更新，不回显、不入库、不入日志；环境变量托管时只读 |
| 重新解析/重新校验 | 页面按钮 | 当前无正式 API | 接口完成前隐藏 |
| 已知例外 | 标记、撤销 | 当前无数据模型和 API | 延期，不能仅做前端弹窗 |
| 映射试跑/规则试算 | 历史范围试跑 | 当前无 API | 延期或明确为后续运营工具 |

“所有列表都支持分页、筛选、排序和导出”的全局约定也过宽。实际应按页面逐项定义，避免为低价值列表补齐无意义排序组合。

### 4.3 `04-数据模型与导入状态`

`paid_in_capital`（实收资本）、`daily_return`（日收益）、`qtd_return`（季度收益）和 `cumulative_payout`（累计派现）已经由解析结果写入每日快照。`market`（市场）和 `account`（账户）已经按明确祖先科目提取并允许为空。

科目保存源工作表和源行；持仓保存原始科目代码、源工作表和源行。当前仍缺统一字段来源查询接口，因此前端只能在有明确接口的页面开放来源入口。

### 4.4 `05-API-接口草案`

原问题是接口文档混合了“目标接口”和“当前已实现接口”，容易误导前端；本轮已通过“当前已实现”“本轮前端必须接入”“明确延期”等状态标记修正。仍缺接口的具体能力维持真实现状：

- 完整分析概览查询；`GET /api/v1/funds/{fund_id}`（产品详情接口）已提供主数据、当前版本摘要和质量状态。
- 公司指数历史序列和公司回撤序列。
- 资产配置展示查询；目前只有 CSV（逗号分隔文件）导出。
- 份额类别每日数据展示查询；目前只有主数据接口和 CSV 导出。
- 独立回撤序列。
- 估值版本历史和版本差异查询。
- 字段来源查询。
- 重新解析、重新校验、已知例外和规则试算。
- 导入初步识别摘要、完整处理日志、邮件附件导航和来源筛选、复核筛选分页与详情。

现有接口参数也少于文档：

- 公司总览没有 `mode`（模式）和 `range`（区间），只支持 `as_of`（估值日）。
- 产品列表只支持名称、状态、估值日和分页，不支持策略、质量、风险和日期范围筛选。
- 持仓只支持估值日和分页，不支持账户、市场、资产类别、合并和排序。
- 数据质量只返回校验结果，不返回版本差异。
- 复核列表没有文档中的筛选、分页和详情接口。

另一方面，业务数据 CSV 导出已经完整存在，前端不应继续在浏览器中导出当前页模拟数据。

邮件设置、受控授权码更新、测试连接、立即同步、暂停/恢复和同步日志接口已经实现。数据保留已有非敏感运维摘要、清理预演和管理员确认执行接口，正式前端必须按权限和安全确认边界接入。

### 4.5 外部可行性报告

该报告已经把基准、行业、VaR、压力测试、流动性和合同限额标为“外部数据或后续阶段”，这一判断正确。

不能直接进入首期需求的内容：

- 申赎推断只能形成不可靠线索，不能形成事件事实。
- 当日盈亏只能做管理估算，不是财务金额。
- 基础持仓归因仍会受到日内交易和现金流影响，不能命名为精确归因。
- 按策略、基金经理、托管机构汇总依赖 Excel 不存在的主数据。
- 基准、行业和风格暴露虽然被列在“第二阶段”，但只要数据源仍限定为估值表，就仍然不可实施。

因此该文件应保留为研究资料，不能替代 `01-产品设计基线`。

## 5. 前端 Demo 逐页审计

### 5.1 全局问题

- 所有页面均调用 `frontend/src/mock` 下的模拟接口。
- 模拟数据生成了 8 个虚构产品及虚构策略、负责人、持仓、风险事件、版本、导入批次、邮件记录和备份状态；与真实三个历史产品无关。
- 所有 `SourceLink`（来源链接）只有悬浮提示，没有点击行为。
- 多数导出在浏览器中只导出当前页模拟数据，没有调用已经存在的后端导出接口。
- 页面顶部大量使用固定日期 `2026-08-22`、固定 `v1` 和固定覆盖率。
- 路由只检查是否登录，不检查页面角色；隐藏导航不能阻止手工输入管理页地址。正式接入时应增加前端路由权限提示，后端权限仍是最终边界。

### 5.2 公司总览

| 页面元素 | 当前情况 | 正确处理 |
|---|---|---|
| 最大回撤 | 固定显示 `-2.34%` | 增加公司指数序列/回撤接口后展示，否则移除 |
| 风险产品 | 浏览器按日收益低于 -2% 临时生成，并伪造规则名 | 只读取风险事件 API |
| 数据质量 | 字段不存在时默认显示“有效” | 未知必须显示等待或缺失，禁止默认正常 |
| 版本 | 固定 `v1` | 显示真实分析运行和估值版本语义 |
| 公司综合收益 | 实际展示公司最新日收益 | 改名“公司当日收益”或返回明确区间收益 |
| 有效产品数 | 实际使用总产品数 | 使用公司指标中的有效权重产品数 |
| 指数“基准 1.0000” | 容易被误解为市场基准 | 改名“指数起始值 1.0000” |
| 导出当前列表 | 只有来源样式，无点击 | 调用正式导出接口 |

公司净资产、覆盖率和指数本身可由 Excel 实现；当前问题是模拟数据、接口缺口和口径标签，不是数据源不可行。

### 5.3 产品列表

- 8 个产品名称、代码、策略和负责人全部是虚构数据。
- 日期、版本和覆盖率固定。
- 策略和负责人不在 2,787 张 Excel 中，应从首期删除。
- 策略、质量、风险、日期范围筛选没有对应的当前后端参数；日期范围控件没有传递任何值。
- 新增、停用和启用只显示“演示”提示；后端已有真实接口，前端尚未接入。
- 导出只导出当前页模拟数据，不是完整筛选结果。

### 5.4 产品详情与概览

- `GET /api/v1/funds/{fund_id}`（产品详情接口）已实现，提供产品主数据、当前版本摘要和质量状态；完整分析概览 JSON（结构化数据）接口仍未实现。
- 详情头部把数据库版本编号直接显示为业务 `vN`，版本语义不够严谨。
- “导出概览”和“查看版本”只有演示提示。
- “查看原表”只跳到导入中心，不能定位当前估值版本的原文件。
- 总资产、负债、净资产和净值可直接实现。
- 最大回撤、当前回撤、现金比例和杠杆率可由 Excel 计算，但当前没有与页面结构匹配的正式产品概览接口。
- 快捷区间按固定 22、66、160、250 条记录切片，不是真实自然月、本年和近一年日期范围。

### 5.5 净值和回撤

- 净值序列和收益计算有已实现页面接口；独立回撤/峰谷页面接口尚未实现，不能把模拟回撤图当作已接入能力。
- 自定义日期有效范围被固定为 2024-01-01 至 2026-08-22，与真实范围 2024-06-24 至 2026-08-24 不一致。
- 区间累计收益取筛选后最后一点的“成立以来累计收益”，不是区间首尾收益，口径错误。
- 回撤曲线来自模拟接口，正式后端没有独立曲线接口。
- 导出缺少文档承诺的回撤和版本信息；后端正式净值导出应作为唯一出口。

### 5.6 资产配置

- 资产配置可由科目映射实现。
- “当前配置/配置趋势”只改变按钮状态，不改变数据。
- “展开原始科目”对所有行固定显示 `110101 沪深A股`。
- 合计权重固定显示 100%，会掩盖负债、未映射科目和分母差异。
- 正式后端只有资产配置导出，没有页面查询接口。

### 5.7 持仓

- 历史日期选择器被禁用。
- 账户固定为“证券账户A/B”，市场固定为“上交所/深交所”，均来自模拟数据。
- 后端已经从真实祖先科目提取可空账户和市场，并保存行级来源；无明确提示时仍为空。
- 首期页面删除穿透合并操作；集中度服务按证券代码归并不改变持仓明细。
- 当前展示接口不支持账户、市场、合并和排序参数。
- 持仓基本字段和可空账户、市场已具备，待前端按真实接口接入。

### 5.8 份额类别

- 产品净资产固定为 50,000,000，导致对账结果没有业务意义。
- 份额实收资本和日收益已经解析并落库；历史原表中的 6 个资本空单元格按空值保存。
- 正式后端只有份额主数据接口和 CSV 导出，没有每日份额展示接口。
- 页面功能保留，待每日份额展示接口接入；不得继续使用固定产品净资产。

### 5.9 数据质量与异常复核

- “重新校验”“重新解析”“标记/撤销已知例外”没有后端接口。
- 版本差异和复核详情均是固定模拟值。
- 后端已有复核列表、确认、发布、驳回、撤回和恢复，可先接这些真实能力。
- 重新解析和重新校验在工程上可实现，但需要定义任务幂等、版本是否重建和审计语义，不能由前端刷新模拟数据代替。

### 5.10 导入中心

- 创建批次、逐文件上传、完成批次、查看批次、重试技术失败、查看校验、受控原文件下载，以及通过估值版本接口发布/驳回/撤回/恢复均有后端基础。
- 当前前端上传只记录文件名，没有向正式服务发送文件内容。
- “选择目录导入”按设计只属于 Windows 客户端，网页版不应显示可用按钮。
- “替代当前版本”没有导入接口语义；发布接口会按估值版本状态处理替代关系。原文件下载已有正式受控接口。
- 浏览器导出的处理报告只包含当前页；后端已有正式完整导出。

### 5.11 邮件接入

- 主机、端口、账号只读查询、测试连接、立即同步和同步记录已有后端接口。
- 管理员可通过正式接口更新受控秘密文件中的授权码；授权码不回显、不进入数据库、响应、日志或审计摘要，环境变量直接托管时拒绝网页覆盖。
- 暂停/恢复自动同步已有管理员接口，开关保存为非敏感系统状态，并在每次定时同步前读取。
- “查看附件”没有邮件附件列表或来源筛选接口，正式页面隐藏该入口。
- 正式页面保留只读配置状态、管理员更新授权码、测试连接、立即同步、暂停/恢复和同步记录。

### 5.12 风险概览与规则

- 风险事件查询和处理已有正式接口，页面可接入。
- 导出按钮只有提示，没有导出实现。
- 风险规则下拉选项是固定模拟值，应从规则接口读取。
- 当前后端真正支持日收益、最大回撤、当前回撤、单票权重、前五大权重和集中度 6 类规则。
- 规则试算没有后端接口，固定提示“触发 3 个历史事件”。
- 文档中的现金比例、杠杆、融资负债、停牌、迟到、对账和净值跳变规则虽然多数可由 Excel 或系统状态实现，但尚未进入规则计算器。

### 5.13 产品、科目、账号、审计、设置和保留管理

- 产品、别名、份额主数据和科目映射核心维护 API 已存在，但页面仍使用模拟数据。
- 产品变更记录、份额历史、科目命中样本均是硬编码内容。
- 科目映射导入和试跑没有 API。
- 账号新增、重置密码、强制退出、登录记录中只有部分操作有接口；页面数据仍是模拟值。
- 审计时间范围控件没有传入筛选条件，也没有操作人筛选。
- 系统设置 API 已存在，页面结构基本可对应；部分设置不会热更新，页面已显示说明。
- 数据保留与备份页面仍使用固定状态，但后端已有非敏感运维摘要、清理预演和管理员确认执行接口，应改接真实结果。

## 7. 建议的首期页面边界

为避免“保留页面”和“尚无页面接口”混用，能力统一分为四类：

- A：已有页面接口，可立即真实接入。
- B：只有 CSV（逗号分隔文件）导出，不等于页面接口。
- C：字段或数据已落库，但页面接口未完成。
- D：明确延期并隐藏。

### 7.1 A：已有页面接口，可立即真实接入

- A：登录、初始化、账号基础管理、审计查询、公司总览、产品列表、产品详情摘要、净值序列、持仓、数据质量、导入批次基本操作、异常复核最小摘要、估值版本生命周期、邮件接口、风险事件/规则接口、系统设置和数据保留接口。
- A：邮箱只读配置、管理员更新授权码、测试连接、立即同步、暂停/恢复和同步日志。
- A：清理预演和管理员确认执行；产品别名、份额主数据、科目映射也按已有接口接入。

### 7.2 C：字段或数据已落库，但页面接口未完成

- C：季度收益、累计派现、份额资本、份额日收益：后端已完成，页面数据接口待接入。
- C：可空市场、可空账户和行级来源：后端已完成；当前持仓响应和统一来源查询待接入。

### 7.3 B/D：只有 CSV 导出或明确延期并隐藏

- B：资产配置和份额每日数据目前只有 CSV 导出，不作为页面保留能力；页面入口隐藏。
- D：完整分析概览、产品分析扩展指标、公司最大回撤/历史曲线、独立回撤/峰谷、版本历史/差异、统一字段来源、导入识别摘要、完整处理日志、邮件附件导航/来源筛选、复核筛选分页/详情。
- D：重新解析、重新校验、已知例外、网页目录导入、科目映射导入、命中样本、测试规则和风险试算。
- D：策略、负责人、基金经理和基准字段及筛选；所有固定日期、固定版本、固定覆盖率、固定业务数字及仅显示“演示”的操作按钮。

### 7.4 明确延期

- D：基准超额、Alpha、Beta、行业/风格、VaR、压力测试和精确流动性。
- D：合同/监管限额自动判断。
- D：精确交易归因、申赎分红事件和财务级盈亏金额。

## 8. 推荐落地顺序

1. 四个确定性解析字段、账户/市场和行级来源已经完成；历史迁移继续保持空值和来源语义。
2. 冻结设计与接口文档，把当前已实现、本轮必须接入和明确延期分开。
3. 前端删除虚构业务承诺，只保留清晰标识的 Demo（模拟原型）外观；随后建立真实 API（接口）适配层替换模拟接口。
4. 先完成公司序列、产品概览、资产配置、份额每日和统一来源查询接口，再开放对应页面。
5. 正式页面接入受控邮件凭据、暂停/恢复和清理预演/执行接口，不复制安全逻辑到浏览器。
6. 高级外部数据能力保持在范围外，除非用户另行批准新数据源和预算。

最终验收原则：页面可以少一个指标，但不能展示一个没有真实输入、没有明确口径或无法追溯的数字。
