# 系统架构与部署

## 1. 总体架构

采用模块化单体（单个可部署后端中按模块组织业务）加一个后台任务进程。当前规模不需要微服务、消息队列或大数据平台。

```text
浏览器 / Windows 客户端
          │ HTTPS
          ▼
      Caddy（自动 HTTPS 反向代理）
          │
          ├── 网页静态文件
          └── 后端接口
                  │
          ┌───────┴────────┐
          │                │
       接口进程          任务进程
          │                │
          └───────┬────────┘
                  │
        PostgreSQL（关系型数据库）
                  │
        原始文件和导出文件目录
```

推荐技术栈：

- FastAPI（Python 后端框架）：接口和权限。
- SQLAlchemy（Python 数据库访问库）：数据访问和事务。
- Alembic（数据库迁移工具）：版本化数据库结构。
- PostgreSQL 16（关系型数据库）：原始标准化数据、版本、任务和审计。
- React（网页界面库）加 TypeScript（类型化 JavaScript）：网页和客户端共用前端。
- Ant Design（企业后台界面库）或同级组件库：表格、表单、抽屉和权限后台。
- Tauri 2（Windows 薄壳）加 WebView2（网页渲染组件）：Windows 客户端。
- Caddy（自动 HTTPS 反向代理）：域名、证书、网页和接口转发。
- Docker Compose（轻量容器编排）：部署和升级。

首期不引入 Redis（内存缓存服务）、Kafka（消息流平台）、Elasticsearch（搜索引擎）或 Kubernetes（容器集群）。数据库任务表足以支撑每天十几到几十个文件。

## 2. 后端模块和模块接口

### 2.1 接入模块

接口：接收文件和邮件元数据，返回导入任务编号。

实现：手工上传适配器、邮件适配器、历史目录导入适配器。

约束：接入模块只负责把输入变成不可变的原始文件记录，不负责直接修改业务数据。

### 2.2 解析模块

接口：输入原始文件记录和解析规则版本，输出标准化候选数据和字段来源。

实现：老式 `.xls` 读取器、新式 `.xlsx` 读取器、表头定位器、科目树构建器、文本数字转换器。

解析器的深模块接口应保持小而稳定：

`parse(file, rule_set) -> ParsedValuation`

调用方不需要知道行号、列号和工作表差异；所有模板差异集中在解析模块内部。

### 2.3 校验模块

接口：输入标准化候选数据和历史上下文，输出分级校验结果。

校验结果包括规则编号、等级、实际值、期望值、差异、来源字段和是否阻断发布。

### 2.4 发布模块

接口：输入可发布的估值版本和发布动作，输出发布结果以及需要重算的日期范围。

发布模块负责版本状态、唯一性、事务和审计，不允许调用方直接更新已发布明细。

### 2.5 分析模块

接口：输入已发布产品数据和分析口径版本，输出产品和公司层面的指标序列。

实现：净值收益、回撤、资产配置、持仓集中度、公司综合指数和风险规则。

所有计算函数尽量返回结果，不在内部直接产生通知等副作用，便于用历史样本测试。

### 2.6 查询模块

接口：面向页面提供已发布和带质量信息的展示数据。

查询模块不读取待发布版本；除导入和复核页面外，普通看板只能看到已发布数据。

## 3. 进程和资源规划

2C4G 服务器建议：

- 接口进程：1 个进程，有限并发；主要是查询和上传，不做 Excel 解析。
- 任务进程：1 个进程，串行处理解析、校验和分析重算，避免内存竞争。
- 数据库：内存上限约 512 MB，启用定期清理和索引。
- 反向代理：内存约几十 MB。
- 系统和文件缓存：预留至少 1.5 GB。

Excel 文件当前每张几十 KB，即使一次导入数百张，也不构成明显内存压力。真正需要控制的是批量任务串行化和单文件大小上限。

## 4. 公网部署

当前环境：阿里云香港公网 Debian 12.10（Linux 服务器系统）、已有域名、尚无 HTTPS 证书和备份服务器。

首期部署步骤：

1. 域名解析到服务器公网地址。
2. 安全组和系统防火墙只开放 80、443，以及受限的 SSH（远程登录）管理入口。
3. Caddy 自动申请和续期 Let's Encrypt（免费证书服务）证书。
4. Caddy 将网页和接口统一代理到同一域名，减少跨域和客户端差异。
5. PostgreSQL 和原始文件目录不直接暴露公网。
6. 运行环境使用 Docker Compose，接口、任务、数据库、Caddy 分开容器但共享一份代码镜像。

必须使用域名访问，不允许生产环境长期使用 IP 加明文 HTTP（未加密网页传输）。

## 5. 文件和数据库安全

- 原始文件保存目录不允许通过 Caddy 直接列目录访问。
- 下载原文件必须经过登录、权限和审计。
- 上传文件先写临时目录，哈希和格式检查完成后再进入正式目录。
- 文件名不能直接作为路径，保存时使用随机对象名；原始文件名只放数据库。
- 上传目录、数据库目录和备份目录分开。
- QQ 邮箱授权码只通过服务器安全配置注入，不写进代码、接口响应或前端日志。
- 生产密钥不提交版本库，不使用公开示例密码。
- 数据库账号按最小权限创建；应用账号不拥有数据库结构删除权限。
- 登录、上传、发布、作废、恢复、规则修改、账号修改全部写审计日志。

建议启用阿里云云盘加密。没有备份服务器时，至少使用阿里云对象存储 OSS（对象存储服务）保存加密数据库备份；它不是新增服务器，成本和维护压力较低，但能避免整台 ECS（云服务器）损坏导致数据全部丢失。

## 6. 备份和滚动清理

### 6.1 数据保留

首期默认：

- 原始 Excel 文件：保留 365 天。
- 已发布的标准化估值、持仓、份额和分析结果：不随原始文件清理，至少保留满足历史分析的期限。
- 导入元数据、哈希、版本、校验和、审计日志：不随原始文件清理。
- 失败任务的临时文件：成功或失败处理完成后 7 天内清理。
- 导出文件和临时压缩包：默认 7 天。

清理任务每天执行一次，先生成待清理清单，再删除到期原始文件；被锁定、正在复核、涉及审计争议或有备份失败标记的文件不得清理。

后端已提供可配置的保留服务：默认 `SOURCE_RETENTION_DAYS=365`（原始文件保留天数），支持预演模式并将候选数、删除数、大小、跳过原因和错误写入审计。只有没有待复核/任务引用、没有审计锁、并且已有成功源文件备份记录的对象才允许删除；删除只作用于受配置根目录约束的原始对象，不删除数据库记录或标准化数据。

### 6.2 备份

- 数据库每天至少一次逻辑备份，保留 30 天滚动副本。
- 原始文件可以按日打包加密后备份到 OSS，保留最近 12 个月或按设置执行。
- 每周执行一次恢复演练或至少验证备份可读性。
- 备份状态显示在系统设置页，备份失败不能静默。

后端已提供数据库逻辑备份适配器：生产 PostgreSQL（关系型数据库）使用 `pg_dump`（数据库逻辑备份命令），本地 SQLite（本地数据库）使用原生备份 API。备份目标必须位于 `DATABASE_BACKUP_DIR`（数据库备份目录）下，命令和审计摘要不包含连接密码；远程 OSS（对象存储）源文件备份在未配置前明确显示 `not_configured`（未配置），不会伪称已完成异地保护。

如果首期暂不购买 OSS，必须接受“服务器硬盘损坏时无法保证恢复原始文件”的风险；这不影响系统功能，但属于明确的部署风险。

## 7. 任务可靠性

数据库任务表字段至少包括：任务类型、资源编号、状态、尝试次数、锁定时间、开始时间、结束时间、错误分类、重试时间。

任务规则：

- 同一资源不能被多个任务同时处理。
- 可重试错误自动重试有限次数；格式错误和业务校验错误不盲目重试。
- 任务写入阶段使用事务；失败回滚，不留下半套发布数据。
- 发布成功后再触发分析重算；分析失败不回滚已经审核通过的原始发布版本，但看板标记为“指标待更新”。
- 任务进程重启后，超时锁定任务可被重新领取。
