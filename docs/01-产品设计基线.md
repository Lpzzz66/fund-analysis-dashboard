# 私募基金估值分析看板：产品设计基线

状态：设计基线 v0.1

## 1. 产品定位

这是一个服务私募基金内部运营、管理层查看和业务员日常处理的估值数据系统。

系统唯一业务数据来源是估值表 Excel（电子表格）文件。系统不承诺从外部行情、交易流水、申赎流水或合同文本中推导不存在于估值表的数据。

产品的核心价值顺序是：

1. 估值表接收稳定。
2. 数据导入可追溯、可重跑、可修订。
3. 资产负债、净值、持仓和份额数据可信。
4. 分析口径明确，并显示数据覆盖范围。
5. 在此基础上提供简洁的管理看板和产品分析。

漂亮的图表不能掩盖缺报、错报和未审核数据。所有总览数字都必须携带数据日期、覆盖数量和质量状态。

## 2. 用户和权限

首期只保留三种角色，避免过早建立复杂的组织权限体系。

| 角色 | 查看看板 | 查看持仓 | 上传/导入 | 审核/发布 | 维护产品 | 维护账号 | 系统设置 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 系统管理员 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 业务员 | 是 | 是 | 是 | 是 | 是 | 否 | 否 |
| 普通看板 | 是 | 是 | 否 | 否 | 否 | 否 | 否 |

当前不做按基金产品隔离，因为用户已明确普通看板和业务员可以看到全部数据。后续如果出现投资经理之间的数据隔离需求，再增加产品授权表，不在首期提前复杂化。

账号体系：

- 本地账号、密码登录、登录失败限制、账号禁用、登录审计。
- 密码使用强哈希保存，不保存明文密码。
- 会话使用服务端会话或安全的不可读令牌，浏览器和 Windows 客户端共用同一套登录接口。
- 普通看板角色默认只读，不能通过前端隐藏按钮绕过权限；后端每个写入接口都必须再次鉴权。
- 首期由管理员重置密码，不做依赖外部邮箱的自助找回。

## 3. 使用形态

### 3.1 网页版

网页版是唯一的主产品。所有页面、交互和接口先以浏览器使用为准，支持现代桌面浏览器。

### 3.2 Windows 客户端

Windows 客户端采用 Tauri（轻量 Windows 应用封装方案）加 WebView2（Windows 内置网页渲染组件）的薄壳方案：

- 业务页面只有一套，网页版和 Windows 客户端不复制业务逻辑。
- 客户端启动后打开同一个 HTTPS（安全网页传输）站点。
- 客户端只负责独立窗口、桌面快捷方式、文件选择、拖拽上传和版本提示。
- 登录、权限、数据请求、导入状态和错误提示全部由网页应用完成。
- 客户端必须限制可加载地址，只允许公司的看板域名，不能成为通用浏览器。
- 首期不做离线看板；没有网络时显示连接失败和重试入口。

这套方案让网页保持灵活，Windows 用户又能获得类似桌面软件的启动体验。由于上传文件本身可以由浏览器完成，客户端不是业务链路的必要依赖。

## 4. 产品信息架构

首期导航分成五组：

1. 总览：公司总览、风险概览。
2. 产品分析：产品列表、产品详情。
3. 数据运营：导入中心、异常复核、邮件接入。
4. 基础配置：产品管理、科目与模板、风险规则、账号管理。
5. 系统管理：审计日志、系统设置、数据保留和备份状态。

普通看板角色只看到总览和产品分析；业务员看到总览、产品分析、数据运营和产品管理；管理员看到全部页面。

## 5. 首期功能范围

### 5.1 必须完成

以下是产品目标清单，不等于当前代码已经全部实现；当前可用范围、页面接入和延期状态以 `docs/05-API-接口草案.md`（接口草案）的状态标记为准。

- 手工上传单个或批量 `.xls`（老式 Excel）和 `.xlsx`（新式 Excel）文件。
- 专用 QQ 邮箱通过 IMAP（邮件接收协议）定时拉取附件。
- 邮箱主机、端口和账号由部署环境提供并只读展示；管理员可在网页更新受控秘密文件中的邮箱授权码，授权码不进入数据库、响应或日志。
- 管理员可暂停或恢复自动邮件同步；暂停不影响已有任务和人工立即同步。
- 原始文件归档、文件哈希去重和导入版本管理。
- 根据科目代码、字段标签和层级解析估值表，不依赖固定行号。
- 产品、份额类别、净资产、资产负债、持仓、资产分类和估值增值入库。
- 资产负债平衡、持仓计算、份额合计、净值变化和关键字段一致性校验。
- 自动发布正常版本，异常版本进入人工复核。
- 产品净值曲线、累计收益、回撤、资产配置、持仓、集中度和基础预警。
- 公司总览、产品覆盖率、最新数据状态、异常数量和综合收益指数。
- 撤回、作废、替代、恢复旧版本和审计记录。
- 产品名称、代码、别名、份额类别、科目映射和规则的页面化维护。
- 原始文件滚动清理必须先由管理员执行清理预演，再以固定确认短语和操作原因确认执行；标准化数据和导入审计记录不删除。

### 5.2 明确不承诺

以下能力不是估值表单一数据源可以准确完成的，首期不放入产品承诺：

- 精确交易归因。
- 现金流调整后的财务级收益金额。
- 行业和主题暴露。
- 需要外部行情的基准超额收益、Beta（贝塔）、Alpha（阿尔法）。
- 需要协方差和行情历史的 VaR（风险价值）和压力测试。
- 精确的流动性天数。
- 合同限额自动判断。

这些能力可以在后续增加新的数据源，但不能用估值表字段伪装成精确结果。

## 6. 核心数据口径

### 6.1 产品净值

- 产品当前展示优先使用表中的“基金单位净值”。
- 历史收益优先使用“累计单位净值”建立复权净值序列。
- 若累计单位净值缺失或不连续，使用单位净值，并结合累计派现进行复核；系统必须将该序列标记为降级口径。
- A、B 份额的净值单独保存；产品级净值使用表中的产品汇总值，不平均 A、B 份额净值。

### 6.2 公司总览

公司总览同时提供两种日期语义：

- 最新状态：每只产品使用自己最近一次已发布估值，适合运营查看，但必须显示各产品数据日期和覆盖率。
- 同日汇总：只汇总用户选择日期已发布的产品，适合横向比较；未更新产品不悄悄沿用旧值。

公司综合收益指数从 1.0000 开始，用前一交易日各产品净资产作为权重链接日收益：

`公司日收益 = Σ（产品前一日净资产 / 公司前一日净资产 × 产品日收益）`

缺少前一日或当日数据的产品不进入该日收益计算，同时显示有效产品数。首期不把不同产品单位净值直接相加或平均。

### 6.3 回撤

回撤基于累计净值序列：

`回撤 = 当前累计净值 / 截至当前最高累计净值 - 1`

界面必须同时显示计算区间、峰值日期、谷值日期、当前回撤和最大回撤。产品成立以来、今年以来、近一年等区间不能混为一个数字。

### 6.4 资产和持仓

- 资产负债表的汇总行、子汇总行和叶子明细行分开保存。
- 持仓分析只使用可识别的叶子持仓，不把父子科目重复相加。
- 市场和账户仅在 Excel（电子表格）的祖先科目名称明确提供时保存，字段允许为空；不根据证券代码、证券名称或产品名称猜测。
- 集中度计算可以按证券代码归并同一证券的多条持仓，但首期页面不提供穿透合并操作，也不把归并结果伪装成新的持仓明细。
- 数量、成本、市价、市值和估值增值使用高精度数值保存，不使用二进制浮点作为数据库主值。

## 7. 关键产品原则

1. 原始文件永不被标准化数据覆盖。
2. 修订产生新版本，不直接改写已发布版本。
3. 所有自动计算都可以重跑，计算结果带分析运行编号。
4. 任何看板数字都能回到产品、估值日、版本和来源文件。
5. 只有阻断级错误阻止发布；警告级问题可以在明确提示后发布。
6. 规则和科目映射由后台维护，不把业务名称写死在代码里。
7. 只建立真正需要的模块，优先保证模块深度和维护局部性。
